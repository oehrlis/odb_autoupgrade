# OraDBA Autoupgrade Extension v0.6.1

**Release Date:** 2026-10-14

## Overview

Version 0.6.1 is a bug-fix release on top of 0.6.0. It fixes three issues found by the molecule scenario of
`oradba.automation`, two findings from the CPU patch tests, and replaces the installation guide stub. Config files,
profiles and the precedence chain are unchanged; an update from 0.6.0 needs no migration.

## Fixes

- `au_gen_config.sh --groups-standard` renders the six `patch1.home_settings.os*_group` lines again: unset
  `AU_GROUP_*` default to the preinstall names, set values are kept (#7)
- `au_run.sh --dry-run` prints the rendered config on stdout (secret values masked) and the java command line on
  stderr, so `au_run.sh --dry-run ... > rendered.cfg` shows exactly what AutoUpgrade would read (#6)
- `gettext` (`envsubst`) and `expect` are listed as prerequisites; minimal `oraclelinux:9` images lack
  `gettext` (#5)
- Profiles with `JDK`, `OCW` or `GI` no longer trigger `unknown keyword` warnings
- The release tarball ships the documentation (`doc/`) and the `jar/` and `patches/` READMEs; up to 0.6.0 it
  contained no documentation
- `au_patch_pin.sh --resolve-mrp` warns when `patches_info.json` has no MRP entry instead of keeping `MRP`
  silently

## Changed

- `cputest-example` profile: `AU_PATCH=RU:19.32,OPATCH,OJVM:19.32,DPBP,JDK,MRP`, `AU_GOLD_IMAGE=YES`, MOS patch
  number as header record. A copy of the old example with the `99999999` placeholder is no longer valid as a
  template
- `au_check_connectivity.sh` also checks `edelivery.oracle.com`; allow it on the proxy before running the check

## Install

```bash
oradba_extension.sh add oehrlis/odb_autoupgrade@v0.6.1
```

Offline: download `odb_autoupgrade-0.6.1.tar.gz` and `.sha256`, run `sha256sum -c`, then
`oradba_extension.sh add "$PWD/odb_autoupgrade-0.6.1.tar.gz"`. See [CHANGELOG](../../CHANGELOG.md) for the full list.
