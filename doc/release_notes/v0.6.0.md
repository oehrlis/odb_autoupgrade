# OraDBA Autoupgrade Extension v0.6.0

**Release Date:** 2026-10-10

## Overview

Version 0.6.0 is the Phase 2 consolidation release. It adds patch profiles, a unified config template
for all three AutoUpgrade modes, edition and OS group control, keystore lifecycle management, JAR update
with version comparison, safe log cleanup, gold image tooling, home generation and verification, and a
complete library refactor shared by all scripts.

## Highlights

- Patch profiles (`--profile`) give a named, reproducible patch set to download, create_home and deploy
- One `au_patch.cfg` template replaces the three mode-specific templates from 0.5.0
- `au_keystore.sh --check / --resave / --backup` complete the keystore lifecycle
- `au_update_jar.sh` version compare, downgrade guard, SHA-256 fleet pinning and keystore staleness warning
- `au_log_cleanup.sh` with a tested keep-set preserving OUA cache, checksum store and run locks
- `au_goldimage.sh` for self-built gold images and manual install on RHEL/OL 9
- `au_gen_config.sh` and `au_home_verify.sh` for config generation and home comparison
- `au_patch_pin.sh` and `au_patch_verify.sh` for post-download pinning and integrity checking
- Full library refactor: `lib/common.sh`, `lib/au_env.sh`, `lib/au_net.sh`, `lib/au_tools.sh`

## Details

### Added

- `bin/au_patch_pin.sh` - write `AU_PATCH` pin file from `patches_info.json` after download; `--resolve-mrp`
  writes the MRP ARU patch ID for CPU-test reproducibility
- `bin/au_patch_verify.sh` - verify a download folder against `patches_info.json` (size and SHA-256)
- `bin/au_gen_config.sh` - render a per-host create_home / deploy config from `au_patch.cfg`; derives groups
  from a source home or uses `AU_GROUP_*` defaults
- `bin/au_home_verify.sh` - compare an Oracle Home against `patches_info.json`, source home binary options
  and OS groups
- `bin/au_goldimage.sh` - self-built gold image: create with `runInstaller -createGoldImage`, verify
  checksum, manual install fallback; prints the `root.sh` command without running it
- `bin/au_log_cleanup.sh` - safe cleanup with an explicit keep-set (OUA cache, checksum store, lock, build
  file, N newest job directories); default is list-only; `--delete --yes` for non-interactive cleanup
- `lib/common.sh` - port of the `odb_datasafe` generic library (logging, error trap, parse_common_opts,
  load_config with SEC-005 checks)
- `lib/au_env.sh` - configuration precedence, file security checks, rendering, pin file parsing
- `lib/au_net.sh` - Java resolution, proxy, truststore, `au_curl` wrapper
- `lib/au_tools.sh` - JAR manifest, keystore helpers, `patches_info.json` parsing, log scan
- `etc/au_patch.cfg` - unified template for download, create_home and deploy; empty lines dropped and named
- `etc/au_keystore.cfg` - minimal console config for `au_keystore.sh` (replaces `etc/test.cfg`)
- `etc/profiles/recommended.profile`, `etc/profiles/19.32.profile`, `etc/profiles/cputest-example.profile`,
  `etc/profiles/21c-cspu.profile` - shipped patch profiles
- `etc/groups/os-fixed-gid.env` - example site group profile using `os*` group names with fixed GIDs
- `--profile <name|path>` option for `au_run.sh`; `--no-pin` to skip post-download pinning
- `AU_EDITION`, `AU_GROUP_*`, `AU_ORACLE_BASE`, `AU_INVENTORY_LOCATION`, `AU_INVENTORY_GROUP` variables
- `AU_JAR`, `AU_KEYSTORE_BACKUP`, `AU_PROFILE_DIR` variables
- `au_keystore.sh --check`, `--resave`, `--backup` operations
- `au_update_jar.sh` version compare, downgrade guard (`--force`), SHA-256 check (`--sha256`),
  keystore staleness warning after JAR update

### Changed

- `lib/au_lib.sh` is now a loader that sources `common.sh` and the `au_*` modules in order
- Caller environment wins over all files and profiles (level 2 beats 2a-7); one snapshot for all files
- Profile precedence at level 2a; pin file wins over profile for `AU_PATCH` (level 6 beats 2a)
- `global.keystore` is rendered only for `-mode download`; create_home and deploy configs carry no keystore entry
- `AU_EDITION` defaults to `EE` when no source home is provided (AutoUpgrade requires an explicit edition)
- All six preinstall OS groups are rendered by default when no source home is provided
- Per-profile download folder: `patches/<profile-name>` when `--profile` is used
- `au_run.sh` calls `au_patch_pin.sh` automatically after a successful download
- `au_run.sh` prints `VDGI_*` / `GOLD_IMAGE` lines from `autoupgrade_patching.log` after every download
- Deprecation WARN on use of `au_download.cfg`, `au_create_home.cfg`, `au_deploy.cfg` (removed in 1.0)
- bash 4.2 or later required

### Removed

- `etc/download_RU19.*.cfg` (14 files) - replaced by profiles
- `etc/download_patch.cfg`, `etc/download_test.cfg` - replaced by `au_patch.cfg` + `AU_PATCH`
- `etc/sample_config.cfg`, `etc/sample_setting.cfg` - regenerate with AutoUpgrade `-patch -create_sample_file`
- `etc/test.cfg` - replaced by `etc/au_keystore.cfg`
- `bin/extension_tool.sh` - extension-template example with no function
- `bin/template.sh` - old template (replaced by the OraDBA-standard template)

### Security

- Env files are refused when the containing directory is group- or world-writable (applies to levels 3-5)
- Owner check accepts the current user or root (numeric UID); symlinks are resolved and the target is checked
- Profile files parsed with an allow-list; unknown keys are fatal
- Pin file and profile files are parsed, never sourced

## Upgrade Notes

See [doc/upgrade-0.6.0.md](../upgrade-0.6.0.md) for the complete migration guide, including:

- Replacing mode-specific templates with `au_patch.cfg`
- Applying `chmod go-w` on `etc/` and site config directories (new security check)
- Adopting `--profile` for named patch sets
- New variables and defaults for edition and OS groups
